yb.download.requirements¶

Preflight for downloading: does yt-dlp have what YouTube now demands?

YouTube makes yt-dlp solve a JavaScript “n challenge”. Without a solver it fails late and cryptically (No video formats found!). Solving needs two things:

  • yt-dlp’s challenge-solver scripts, shipped by yt-dlp[default] (the yt-dlp-ejs package), which yb[download] depends on;

  • a JavaScript runtime. Deno is the one yt-dlp enables by default, and the one that works.

Deno’s installer puts it in ~/.deno/bin and only adds that to PATH for interactive shells, so a cron job or service often can’t see it. This module also looks there, and yt_dlp_runtime_opts() hands yt-dlp the explicit path, so downloads work without touching PATH.

>>> from yb.download import check_requirements
>>> problems = check_requirements()
>>> print("\n\n".join(problems) or "ready")

Nothing here raises: missing pieces are reported (and, by default, warned) with the command that fixes them.

yb.download.requirements.check_requirements(*, warn=True, which=<function which>, search_dirs=None, find_spec=<function find_spec>, run=<function run>, import_module=<function import_module>, check_deno_version=True)[source]¶

Check what YouTube downloads need, and say how to fix what’s missing.

Never raises. Each problem is a message ending with the fix.

Parameters:

  • warn (bool) – Also emit each problem as a DownloadRequirementWarning.

  • which (Callable[[str], str | None]) – See find_js_runtime().

  • search_dirs (Iterable[Path] | None) – See find_js_runtime().

  • find_spec (Callable[[str], object | None]) – Module lookup for has_module().

  • run (Callable[..., CompletedProcess[str]]) – Subprocess runner for deno_version().

  • import_module (Callable[[str], object]) – Importer for min_deno_version().

  • check_deno_version (bool) – Also run deno --version and compare it with yt-dlp’s minimum. The download preflight turns this off: it spawns a process, which belongs in an explicit check, not in a download.

Return type:

list[str]

Returns:

The problems found; empty when downloads should work.

yb.download.requirements.deno_search_dirs()[source]¶

Where Deno lives when it isn’t on PATH.

This Python’s scripts dir and its interpreter’s dir (a pip-installed Deno, e.g. yt-dlp[deno], in a venv that isn’t activated: yt-dlp looks there too), then the installer’s $DENO_INSTALL/bin and ~/.deno/bin.

Return type:

tuple[Path, ...]

Ask runtime for its version (deno --version); None if unknown.

yb.download.requirements.with_runtime_opts(opts)[source]¶

opts plus the preflight’s runtime path, unless opts names runtimes.

The first call per process runs check_requirements() (warning, never raising). An explicit js_runtimes in opts always wins, and skips the check: the caller has chosen a runtime.

dict
