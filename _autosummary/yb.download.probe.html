yb.download.probe¶

Online checks for servers: do the configured cookies still get past YouTube?

A cookies file exported from an everyday browser session goes stale: YouTube rotates the session cookies as a security measure, after which every client gets “Sign in to confirm you’re not a bot”. check_cookies() finds that out before the first real download: it checks the file holds a logged-in session, then reads one known public video with it, on a private copy so the check never rewrites the file. check_po_token_server() pings the PO-token provider’s server. yb check --online runs both.

>>> from yb.download.probe import check_cookies
>>> print("\n".join(check_cookies()) or "cookies ok")

yb.download.probe.check_cookies(cookies_file=None, *, probe_url='https://www.youtube.com/watch?v=jNQXAC9IVRw', fetch_info=<function _probe_info>)[source]¶

Problems with the cookies downloads would use (empty when they work).

Checks that the file holds a logged-in session, then reads probe_url with it (one metadata fetch; yt-dlp works on a copy, so the file is left as it was). With no file configured there is nothing to check.

Parameters:

  • cookies_file (Union[str, Path, Literal[False], None]) – As in download_youtube_video().

  • probe_url (str) – A public video every working setup can read.

  • fetch_info (Callable[..., Any]) – (url, *, cookies_file, extra_opts) metadata fetcher; a fake in tests.

Returns:

no or a missing file where one was named, not a logged-in session, rotated or expired, refused by the bot check, or the probe failed for another reason.

Return type:

list[str]
